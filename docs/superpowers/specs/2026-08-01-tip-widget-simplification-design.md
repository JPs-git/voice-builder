# TipWidget 精简与轮播修复设计

## 目标

在保留初始隐藏、定时显示/隐藏、悬停暂停、关闭后可从 ℹ️ 入口重开的交互前提下，修复提示不会切换的缺陷，并移除不必要的状态机和 DOM 动画监听。

## 设计

`TipWidget` 保持现有 `tips?: string[]` 与 `interval?: number` 接口。

组件内部改用四个独立状态：

- `isVisible`：卡片当前是否展示；初始为 `false`。
- `isPaused`：鼠标悬停时为 `true`。
- `isDismissed`：用户关闭后为 `true`，停止自动轮播并展示 ℹ️ 入口。
- `tipIndex`：当前提示索引。

未关闭且未暂停时，组件维护一个单次定时器：

- 初始隐藏，首次到期后显示卡片。
- 每次到期在隐藏和显示之间交替。
- 仅在隐藏切换为显示时选择下一条提示。
- 使用随机选择；当提示不少于两条时，必须避开当前索引，防止连续重复。
- 鼠标离开卡片后重新开始完整的 `interval`，不保留悬停前的剩余时间。
- 点击关闭立即停止定时器并使卡片退出；ℹ️ 入口在 CSS 退出动画后显示。
- 点击 ℹ️ 立即随机展示一条非重复提示，并恢复自动轮播。
- 卸载时清除定时器。

CSS 继续处理卡片的平移与透明度过渡；不再由 JavaScript 监听 `transitionend`，也不保留 `closing` 状态或 DOM ref。

## 测试

新增 `TipWidget` 组件测试，使用 Vitest fake timers：

- 初始卡片隐藏，首次 interval 后显示。
- 定时器按显示/隐藏交替，并只在再次显示时换提示。
- 多条提示时随机选择不与上一条重复；单条提示可正常重复。
- 悬停暂停轮播，离开后以完整 interval 恢复。
- 关闭停止轮播、显示 ℹ️；重开后恢复展示与轮播。
- 卸载后不遗留定时器或触发状态更新。

## 非目标

- 不保存关闭状态到本地存储。
- 不改变提示文案、位置、默认间隔或外部调用方式。
- 不修改全局应用状态与音频分析流程。
