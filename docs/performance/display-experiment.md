# 移动端显示链路实验：批量共振峰散点

2026-10-01。以已完成频谱FFT、基频去重、倒谱FFT的 `fcc2ce6` 为基线。

本轮确认，共振峰图大量独立点图元的处理是当前固定音频显示链路的重要瓶颈。改用批量散点后，最终源码三组真机对比的RAF间隔P95均从83.0ms降到49.9ms，>100ms间隔合计20→8次。仍有个别>200ms停顿，不能据此宣称录音已无卡顿、稳定60fps或低端机验收完成。

## 测量范围与身份

- Redmi K70E / 2311DRK48C，Android 15，Chrome 125.0.6422.72；USB连接，页面全程前台。竖屏407×798 CSS像素，DPR 3。
- 使用相同SHA-256校验的 `aoe` 固定PCM，16kHz，每1024样本/64ms输入一个chunk。连续循环原信号，不在循环边界重置pipeline，不丢样本。迟到时每个任务补一个chunk，记录迟到与积压。
- 临时诊断生产构建与应用共享实际AudioEngine、Zustand store、ECharts单例。用真实录音按钮获得 `useAnalysis` 的实际回调，经过pipeline、store、React和两个可见图表；没有打开麦克风或AudioContext。
- 预热11秒、稳态15秒，标准短测407个chunk、416768样本/26.048秒音频。50ms分析窗与64ms输入对齐导致恰好10秒不足1000帧，因此改用11秒填满历史窗口。停止flush及输出校验不计入稳态。
- 轻量采样用于前后比较；详细store/Storage/chart/LongTask计时与CPU profiler分开采集。分位数取排序后的 `floor((n−1)×q)` 项。
- 基线页面4175是冻结的 `fcc2ce6`；候选页面4176。原始结果每份包含HEAD、源码哈希、探针哈希、PCM身份、可见性和实际输入记录。最终候选源码为该HEAD加本轮FormantChart改动；其文件SHA-256为 `592e913cb5eea90636b4a7fc71df08094ab4c30cf2eb15eee1e9b0732070488a`。
- 探针SHA-256：`61a3baa7901d80981eb6d9cfae40d65fa3fc66cd9a84fcf8193631bab8494c87`；最终诊断JS `index-ClD2xxhg.js` SHA-256：`8482d588a228565c77435c1decebda29834ec3bfdf0dfd50caa6c285b7ab25d3`。正常产品构建不含探针。

主checkout的已有修改未参与实验。代码开发位于 `.worktrees/fix/fft-allocation`，原始工具、构建与结果位于仓库根忽略目录 `.superpowers/measurements/2026-10-01-display-experiment/`，没有追踪进Git。

## 原因定位

分析数据步长为10ms/100帧每秒，但输入每64ms到达一批，现有图表已通过RAF合并更新，稳态约15次更新/秒。将图表简单限制到15fps不能保证消除当前成本。

三组临时“跳过图表setOption”消融，保留实际DSP、store和React工作：RAF间隔P95从83.1–99.6ms变为16.7ms，>100ms间隔从每组7–10次变为0，输入迟到P95从114.5–298.3ms变为4.4–5.2ms。这仅用于定位绘制成本；不显示新数据的消融不能作为产品方案或显示正确性证明。

基线独立详细采样，15秒稳态内：

| 工作 | 次数 | 平均耗时 | P95 |
| --- | ---: | ---: | ---: |
| FormantChart setOption | 228 | 35.37ms | 79.6ms |
| F0Chart setOption | 227 | 8.28ms | 18.2ms |
| appendFrame，含订阅及持久化 | 1498 | 0.100ms | 0.3ms |
| 原生preset Storage.setItem | 1498 | 0.063ms | 0.2ms |

Storage计时不含此前JSON序列化；序列化包含在appendFrame内，二者不能重复相加。持久化确实每帧执行，但这份数据不支持把它当作主要瓶颈。

独立CPU采样在窗口填满后开始，持续约15.0秒。ECharts DataDiffer、ZRender Group遍历、Symbol更新、Canvas绘制、clone/merge占明显采样时间；GC约2.06秒。该采样包含末尾停止与输出处理，不能直接套入轻量稳态指标，也不能将所有GC归因于某一种对象。结合源码发现：移动端原本用宽度为0的line加 `showSymbol` 实现点图，每帧窗口最多3×1000点，仍维护大量独立图元。

## 单变量改动

只改变宽度≤768px的共振峰点绘制：使用scatter，100点起启用large批量绘制，显式保持opacity 1。保留全部原始点、空值、短峰、时间轴、目标区间、颜色、2px标记、DPR和更新频率。宽屏仍用line。

独立审查及真实ECharts 5.6探针发现，large模式遇到空值时可能使点的命中区域失效，且不提供逐点强调图元。因此存在 `onFrameClick` 回调时使用普通scatter；回调的出现/移除会立即刷新模式，并取消旧的待绘制任务。当前分析页不传此回调，其性能收益不受保护条件影响。

视觉差异：ECharts对小于4px的large标记可使用矩形快速路径，2px点会更像像素小方块。真机截图确认数据形状、间断、颜色和目标区域保持可读；不能宣称圆形标记的像素外观完全一致。large模式没有逐点强调效果，轴提示仍保留。

## 真机对比

先进行临时候选预览三组交替测试，再对加入点选保护的最终源码进行三组交替测试。每组均重新加载，输入、预热、采样时长与观察方式相同。

预览三组：基线RAF间隔P95为83.0–83.2ms，候选49.9–66.3ms；>100ms间隔每组9–11→0–2次。最终源码结果如下，单位ms；“长间隔”指15秒稳态内RAF间隔>100ms。

| 对比与顺序 | 基线P95/P99 | 候选P95/P99 | 长间隔：基线→候选 | 输入迟到P95：基线→候选 |
| --- | ---: | ---: | ---: | ---: |
| baseline-light07 → final-guard-light02 | 83.0 / 116.2 | 49.9 / 83.0 | 7 → 5 | 349.9 → 145.6 |
| final-guard-light03 → baseline-light08 | 83.0 / 116.3 | 49.9 / 83.1 | 8 → 1 | 325.3 → 61.2 |
| baseline-light09 → final-guard-light04 | 83.0 / 116.2 | 49.9 / 83.1 | 5 → 2 | 135.1 → 50.2 |

最终三组P95约降低40%，长间隔合计减少60%。但候选各组最长间隔分别265.6、282.3、132.9ms，仍有罕见长停顿；不能只报告分位数而忽略尾部。此前一份最终源码复核 `final-guard-light` 同样有5次长间隔，P99为99.6ms，没有剔除这份较差结果。

详细候选采样用于归因，不与轻量测试混为一个样本：FormantChart更新234次，平均16.30ms，P95 36.8ms，相比基线P95降低约54%；F0图235次。共振峰图finished事件间隔P95由136.5ms变为117.0ms，P99由179.7ms变为141.2ms，仍未全面满足原计划的均匀更新目标。LongTask次数61→30。候选chunk回调P95约28.7ms，反而高于基线14.8ms；不能宣称DSP变快，也没有足够证据判定是调频、JIT或其他系统因素。

另采集最终保护源码的详细样本，不加入轻量验收分位数：共振峰图232次提交，每次3000个数据项，setOption平均16.94ms、P95 37.2ms，LongTask 35次。最新提交时间与最新store时间每次一致。由原始提交起点重新计算、两端都在稳态内的间隔如下：

| 详细样本 | 实际数据提交间隔P95/P99 | 提交时模拟信号年龄P95/P99 |
| --- | ---: | ---: |
| 基线 | 117.9 / 199.2ms | 209.4 / 236.0ms |
| 临时预览 | 101.8 / 128.2ms | 132.8 / 167.6ms |
| 最终保护源码 | 102.6 / 120.6ms | 128.9 / 250.4ms |

模拟信号年龄为提交起点 `atMs−1000×latestChartInputTime`，含分析及计时器排队，并非屏幕呈现延迟。最终年龄P99比基线更差，不能宣称所有新鲜度尾部指标改善。最终提交最长间隔211.2ms，P95也仍略高于100ms目标。上述重新计算排除跨越稳态边界的首个间隔，与probe原有finished分段summary的边界规则不同。

RAF表示浏览器提供绘制机会的间隔，不是实际屏幕帧率；setOption包含同步ECharts工作，finished是ECharts事件，不是合成器呈现证据。实际数据提交时间及完整点数需结合原始chart tape检查，不能只用store时间或平均FPS。

设备一直USB供电。预览对比开始电池温度31.8℃，最终三组轻量对比结束34.1℃；这些是电池温度，不能证明CPU未发生降频或替代十分钟热机验证。

## 正确性与功能验证

- 31份有效真机输出，包括基线、绘制消融、候选、最终代码、详细/profile、UI起停及清理流程复核，与同一生产DSP源码的独立Node参考对照。标准短测停止前2600帧，flush后2605帧、保留1000帧；核对计数，并比较保留窗口及最新完整帧的全部标量和全频谱Float32位指纹，均匹配。未逐帧导出被历史窗口移除的较早帧；指纹匹配也不是逐字节无碰撞证明。
- 每份结果核对输入总数、可见性、无溢出/取消/异常及单例身份；不把UI短测的不同音频时长混入性能表。
- 新增回归检查先失败后通过：完整1000点窗口、空值与单点峰保留，以及回调新增/移除时的模式切换。既有目标区间、隐藏图例和桌面选项测试保留。
- 实际ECharts探针复核空值点选保护、轴提示索引与原值、目标区间、隐藏/恢复、99/100点阈值、scatter/line宽度往返。该探针为SVG SSR，不证明Canvas性能或原生触摸行为。
- 最终代码真机检查：停止后仍有1000帧；F1隐藏/恢复；实际HTML轴提示在空值区域显示时间和三个`--`；清空后帧数0；再次录音与停止；实际旋转407×798→870×301→407×798、保留窗口和布局切换。检查后恢复原旋转设置 `lock 0`，销毁诊断补丁、停止模拟采集并清空图表。
- `npm test`：52文件、386测试通过；`npm run build`通过，仅有原有的大包提示；`npx tsc --noEmit`通过。独立代码审查的问题已修复并复核。

## 后续方向与边界

优先复查批量绘制后的尾部热点，再做局部setOption单变量实验：只更新数据与移动时间轴，单独处理目标区间、图例和布局变化，比较实际提交的新数据间隔与尾部延迟。完整option仍可能带来重复配置处理和分配，但旧CPU采样不能证明它已经成为新的最大热点。

如果仍缺绘制余量，再独立比较较低的统一显示频率或DPR上限。分析频率、原始PCM与1000帧历史继续保留。若新trace确认DSP长批次持续阻塞主线程，再设计Worker会话、队列和flush协议。

真实麦克风/外放、十分钟热机、录音时交互、后台恢复及实际中低端Android尚未验证。当前结论只覆盖K70E固定PCM到真实显示链路，不能当作这些场景的验收。

探针的分段summary中，帧序号和保留数量为汇总时的末态，不可用它们独自证明窗口在整个稳态都已填满；详细tape对此另行核对。轻量模式不采chart tape。旧runner在finally忽略destroy异常，因此旧结果本身不证明清理完成；本轮UI报告明确保存销毁后状态，探针自检验证恢复逻辑，后续runner已改为保存并强制检查清理状态，并通过手机短测复核。

结束时手机已切到4176正常产品构建，确认没有诊断模块、模拟采集或进行中的录音；该预览保留供用户试录音。诊断服务已停止，原始文件保留。需要继续测量时另启对应诊断构建，不能直接在正常页面调用探针。
