# FFT 单变量真机实验（2026-09-30）

## 结论

仅替换 fftMagnitudes 内部计算后，Redmi K70E 的三组安静录音测试均有明显改善：15秒窗口内 RAF 间隔 P95 从215.9–232.5ms降到49.8–66.4ms，超过100ms的间隔从87–95次降到0次。仍有长任务，不能宣称稳定30/60fps或所有场景已修复。

## 变更范围

基线为 master 90ac031；候选为同一提交加 fix/fft-allocation 工作区的 FFT 与测试改动。不包含 PR #45 的图表优化。仅频谱路径使用 Float64 实部/虚部工作数组、预计算旋转因子、位逆序和 Hann 窗；单个缓存按 FFT 长度和输入长度更新，不无限积累。每次返回新的 Float32Array，避免后续计算覆盖历史频谱。

分析频率、静音处理、线程、图表调度、窗函数、归一化及 dB 下限保持不变；倒谱使用的公共 complexFft/ifft 未修改。此实验把 FFT 内部实现作为一个变量，不能单独归因预计算与减少分配各自的贡献。

## 环境与方法

- Redmi K70E / Android 15 / Chrome 125.0.6422.72（此前设备查询；UA降熵可能显示 Android10 / Chrome125.0.0.0）。
- USB reverse；生产构建带 source map；关闭 CPU profiler 与投屏，不带 perf 参数。
- 基线 localhost:4173，候选 localhost:4174。
- 候选 JS：index-C3KDWgZO.js；SHA256：1F576C36388AA17EFF6DB20057772D5A65E4F9F80E004C16E02D9129BC1FEF08。
- 基线 JS：index-CTJqaRlb.js；SHA256：E461F1C07B708627D1353B0C9DF54BAB1C5AA1ACAC27D5BAAB8B2C2639BAF2C3。
- 每轮重新加载，开始录音后预热10秒，再采样15秒；顺序 A1、B1、B2、A2、A3、B3。
- 主线程阻塞会延迟导出，因此统一分析探针开始后的前15秒；跨窗口长任务截断。长任务占用不包含短于50ms的任务。
- 请求保持安静；各轮反馈采样均未显示有效频率。这不是经过声学校准的静音输入。
- 开始与导出时均检查页面在前台；未记录完整可见性事件。测试尾段电池温度38.0℃、USB供电、电量95%；不是CPU温度，未持续采集温度。

## 手机端独立计算验证

停止录音后，在同一手机页面加载原版/候选 FFT 的独立 bundle。固定400点输入（220Hz与1300Hz叠加），2048点 FFT；各预热50次，按 A/B/B/A/A/B 顺序每轮100次。该微基准不代表整条录音链路。

- 原版100次累计：174.8、161.1、170.5ms，合计506.4ms。
- 候选100次累计：43.2、31.2、31.7ms，合计106.1ms，约4.8倍吞吐。
- 固定输入所有输出 bin 的最大绝对差：0dB（Float32输出）。
- 有限样本及计时精度限制下的观测，不证明所有输入数学上完全相等。
